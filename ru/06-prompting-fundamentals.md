# Основы промптинга для Claude Code

**Модуль:** 2. Быстрый старт | **Время:** ~35 мин теории + 20 мин практики

---

## Суть урока

Промпт (промпт — текстовый запрос к AI) — это техническое задание для агента (агент — автономная программа-исполнитель). Плохое ТЗ — плохой результат, и это не вина подрядчика. Хорошее ТЗ — точный результат с первого раза. Этот урок учит писать хорошие ТЗ для Claude Code. Принципы работают в любом AI-ассистенте (ChatGPT, Gemini, Claude в браузере): меняется только место, куда ты вставляешь текст.

---

## Ключевые концепции

- Claude Code = блестящий подрядчик с доступом к твоим инструментам
- Конкретика в промпте напрямую определяет качество результата
- Разница между плохим и хорошим промптом на реальных примерах
- Plan Mode: когда не знаешь что хочешь — используй его
- Зависимость качества вывода от твоего понимания предметной области

---

## Теория

### Claude Code — подрядчик, не волшебник

Есть соблазн думать о Claude Code как о волшебной палочке: «скажу что хочу — получу готовое». Правильнее думать иначе:

**Claude Code — блестящий подрядчик** с огромным опытом, который умеет строить практически всё. Но у него есть доступ только к тому, что ты ему дал:

- Файлы в открытой папке проекта
- Инструменты которые ты подключил
- Информацию которую ты описал в задании

Он не знает твой бренд, твоих клиентов, твои предпочтения по дизайну — если ты не объяснил.

Именно поэтому **размытые запросы дают размытые результаты**, а конкретные запросы дают точные результаты.

🎨 **Образ:** Промпт — это техническое задание прорабу. «Постройте что-нибудь красивое» — прораб построит что-то. Может, тебе понравится, может нет. «Постройте двухэтажный дом 120 кв.м, три спальни, гараж на одну машину, фасад кирпич, кровля металлочерепица» — прораб построит именно это.

### Анатомия плохого промпта

Разберём типичный пример плохого запроса:

```
Построй мне сайт для бизнеса по выгулу собак
```

Что агент не знает из этого запроса:

- Какой стиль и цвета? (Строгий корпоративный? Игривый и яркий?)
- Какие секции нужны? (Только главная страница? Цены? Отзывы? Форма записи?)
- Для какого города или региона? (Нужна ли карта?)
- Одна страница или несколько?
- Нужна ли форма записи? Онлайн-оплата?
- На каком языке?
- Есть ли логотип?

Агент сделает что-то. Но это «что-то» будет основано на его предположениях, а не на твоих реальных требованиях. В результате ты получишь:

- 3-4 итерации правок («нет, это не то, сделай вот так»)
- Много потраченных токенов (токены — минимальные единицы текста для AI)
- Разочарование

### Анатомия хорошего промпта

Тот же запрос, написанный правильно:

```
Построй landing page для бизнеса по выгулу собак в Москве. 

Требования:
- Hero-секция: заголовок «Профессиональный выгул собак», подзаголовок «Каждый день, любая погода, опытные грумеры», кнопка «Записаться»
- Секция услуг: 3 карточки — одиночный выгул (1 час, 500₽), групповой выгул (1.5 часа, 350₽), дрессировка+выгул (2 часа, 800₽)
- Секция отзывов: 3 блока с текстом и именем клиента (придумай)
- Форма записи: имя, телефон, порода собаки, выбор услуги, кнопка «Оставить заявку»
- Футер: телефон +7 (999) 123-45-67, email info@dogwalk.ru, Instagram @dogwalk_moscow

Стиль: цветовая схема — синий #2563EB и белый, шрифт системный, карточки с закругленными углами
Технологии: только HTML и CSS, никаких фреймворков, один файл index.html
Адаптивный: работает на мобильных
```

Агент сделает именно это. С первого раза. Без итераций.

**Что изменилось:** ты дал конкретику по каждому аспекту который агент иначе угадывал бы.

### Пять элементов хорошего промпта

🎨 **Образ:** Пять элементов промпта — как пять вопросов журналиста: Кто? Что? Где? Когда? Зачем? Хороший репортаж без хотя бы одного из них теряет смысл. Хороший промпт — то же самое.

**1. Результат (что в итоге)**

Не «создай автоматизацию», а «создай Python (Питон — язык программирования)-скрипт, который...»

**2. Контекст (контекст — содержание разговора видимое AI) (зачем это)**

«Этот скрипт будет запускаться каждый день в 9:00 и отправлять...»

**3. Ограничения (чего не делать)**

«Не используй внешние библиотеки кроме requests. Не создавай базу данных — только CSV-файл.»

**4. Примеры (как должно выглядеть)**

«Формат письма такой: Тема — «Отчёт за [дата]», тело письма — таблица с колонками Имя, Сумма, Статус»

**5. Критерии готовности (как проверить)**

«Готово когда: скрипт запускается без ошибок, создаёт файл report.csv, отправляет письмо на test@email.com»

Необязательно всегда использовать все пять — иногда достаточно двух-трёх. Но чем сложнее задача, тем важнее каждый элемент.

### Plan Mode: когда ты сам не знаешь что хочешь

🎨 **Образ:** Plan Mode — как консультация с архитектором перед стройкой. Ты говоришь: «Хочу уютный дом для семьи с детьми». Архитектор задаёт вопросы: сколько детей? есть ли гараж нужен? какой бюджет? И потом предлагает план — не стройку. Сначала смотришь на чертёж, потом разрешаешь класть кирпичи.

Бывает ситуация: ты знаешь проблему, но не знаешь как её решить технически. Или знаешь результат, но не понимаешь из каких частей он должен состоять.

Для этого в Claude Code есть **Plan Mode**.

Как активировать: напиши запрос и добавь в конце «Прежде чем начать — задай мне уточняющие вопросы» или включи Plan Mode через интерфейс: в терминале переключение режимов идёт клавишами Shift+Tab (или командой `/plan`), в приложении для компьютера режим выбирается в списке рядом с кнопкой отправки.

Пример:

```
Хочу автоматизировать ежедневную рассылку дайджеста новостей о недвижимости своим клиентам. 
Прежде чем начинать — задай уточняющие вопросы чтобы понять что именно нужно построить.
```

Агент задаст вопросы типа:

- «Откуда брать новости — из конкретных сайтов или через API (эй-пи-ай, Application Programming Interface — интерфейс программирования приложений)?»
- «Сколько новостей в каждой рассылке?»
- «Нужна ли персонализация по городу клиента?»
- «Как хранится список клиентов — Google Sheets, CRM (си-ар-эм, Customer Relationship Management — управление отношениями с клиентами), CSV?»
- «В какое время отправлять?»

После твоих ответов агент составит план — и только потом начнёт строить.

**Когда использовать Plan Mode:**

- Задача сложная и многокомпонентная
- Ты не уверен как правильно её разбить на части
- Хочешь убедиться что агент правильно понял до начала работы
- Стоимость ошибки высокая (много времени или денег)

### Зависимость качества от твоего понимания

Это неудобная правда, которую важно принять в начале:

**Чем лучше ты понимаешь предметную область — тем качественнее результат агента.**

Если ты просишь агента построить newsletter automation, но не понимаешь как работают email-рассылки (SPF/DKIM, отписки, bounce-handling) — ты не поймёшь хорошо ли агент сделал. Ты получишь что-то работающее в теории, но потенциально со скрытыми проблемами.

Если ты понимаешь как работают рассылки — ты дашь правильное задание, заметишь если агент упустил важное, и сможешь проверить результат.

Это не значит что нужно стать разработчиком. Но нужно понимать **бизнес-процесс** который автоматизируешь:

- Как работает процесс сейчас (вручную)?
- Какие edge cases встречаются?
- Что значит «сделано правильно» для этого процесса?

Именно поэтому лучшие строители агентных систем — это люди которые сначала понимали предметную область (маркетинг, продажи, финансы, логистика), а потом научились инструментам.

### Итерации — норма, не провал

🎨 **Образ:** Художник делает эскизы, потом набросок, потом детальную картину. Никто не ожидает от первого мазка кисти законченного полотна. Первый промпт — это твой набросок. Задача не «идеально с нуля», а «дойти до цели за минимум шагов».

Даже хорошо написанный промпт редко даёт идеальный результат с первого раза. И это нормально.

Паттерн работы с агентом (проценты ниже — ориентир, а не измерение):

1. Написал хороший промпт → получил 70-80% нужного
2. Увидел что не так → уточняющий промпт на конкретные правки
3. Получил 90-95% → ещё раз по мелким деталям
4. Готово

Цель хорошего промпта — не «идеально с первого раза», а «как можно ближе к цели с минимальным количеством итераций».

Плохой промпт даёт 30-40% с первого раза и требует 5-7 итераций.

Хороший промпт даёт 70-80% с первого раза и требует 1-2 итерации.

Разница — в 3-4 итерации. При сложных задачах это часы работы.

### Quick Reference: плохой промпт → хороший промпт

| Плохой промпт | Хороший промпт | Почему лучше |
|---|---|---|
| «Сделай сайт» | «Создай landing page на HTML+CSS, одна страница, синий+белый, секции: hero, услуги, форма» | Конкретный результат, стиль, структура |
| «Напиши скрипт» | «Напиши Python-скрипт который читает CSV, фильтрует строки с суммой > 1000, сохраняет в новый CSV» | Язык, вход, логика, выход |
| «Автоматизируй email» | «Создай воркфлоу (воркфлоу — рабочий процесс, поток задач): каждый понедельник собирай 5 новостей из RSS, генерируй HTML-письмо, отправь через Gmail API по списку из Google Sheets» | Расписание, источник, формат, канал, получатели |
| «Исправь ошибку» | «В файле main.py строка 42 — TypeError: expected str, got int. Функция process_data получает число вместо строки из API-ответа» | Файл, строка, тип ошибки, контекст |
| «Сделай красиво» | «Добавь: скруглённые углы 8px, тень карточек, отступы 24px между секциями, шрифт Inter» | Конкретные параметры дизайна |

## Практика

**Задание:** Написать один плохой промпт, переписать его хорошо, сравнить результаты.

**Шаг 1 — Плохой промпт (5 мин):**

1. Открой Claude Code в пустой папке
2. Напиши этот промпт (дословно):
   ```
   Создай форму для сбора заявок от клиентов
   ```

3. Посмотри что получилось. Запиши: чего не хватает? Что агент придумал за тебя?

**Шаг 2 — Хороший промпт (10 мин):**

1. Напиши новый промпт по пяти элементам:
   - **Результат:** «Создай HTML-форму...»
   - **Контекст:** «...для записи клиентов на первичную консультацию по [твоя тема]»
   - **Поля:** перечисли конкретные поля которые нужны
   - **Стиль:** цвета, шрифты, внешний вид
   - **Критерий готовности:** «Форма должна работать без JavaScript (ДжаваСкрипт — язык программирования)-фреймворков»
2. Запусти этот промпт
3. Сравни результат с первым

**Шаг 3 — Анализ (5 мин):**

Ответь для себя:

- Сколько итераций потребовалось для первого промпта?
- Сколько для второго?
- Что тебе пришлось объяснять отдельно в первом случае?

## Частые ошибки

❌ **Ошибка:** Писать один огромный промпт на 500 слов с первого раза.

✅ **Правильно:** Начни с главного (результат + контекст), получи первую версию, потом уточняй итеративно. 2-3 коротких промпта лучше одного гигантского.

❌ **Ошибка:** Не указывать ограничения — «не используй фреймворки», «только Python», «без базы данных».

✅ **Правильно:** Без ограничений агент выберет свой стек. Если тебе важно что именно использовать — скажи это явно. Ограничения экономят итерации.

❌ **Ошибка:** Не проверять результат и деплоить (деплой — развёртывание, публикация) «как есть».

✅ **Правильно:** Всегда проверяй: запускается ли без ошибок, делает ли то что ты ожидал, обрабатывает ли edge cases. Используй Plan Mode если не уверен как разбить задачу.

## Ключевые выводы

> Плохой промпт = плохое техническое задание. Агент сделает что-то — но не то что нужно тебе.

> Пять элементов хорошего промпта: результат, контекст, ограничения, примеры, критерии готовности.

> Plan Mode — используй когда не знаешь как разбить задачу на части. Агент задаст правильные вопросы.

> Качество результата зависит от твоего понимания предметной области. Агент строит по твоим чертежам.
