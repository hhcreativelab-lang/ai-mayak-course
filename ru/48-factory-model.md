# Урок 48: Factory Model — шаблоны и повторяемость

**Время:** ~25 мин теории + 30 мин практики

---

## Суть урока

Первый дом строишь 3 месяца. Десятый — 3 недели. Потому что у тебя уже есть шаблоны стен, проверенные поставщики, и бригада знает что делать. Factory Model — это когда каждый новый проект похожего типа ты делаешь быстрее и дешевле предыдущего. А клиенту ты это продаёшь дороже — потому что быстрее = ценнее.

---

## Ключевые концепции

- **Factory** — система шаблонов для масштабирования: 80% стандарт + 20% кастомизация
- **Template репо** — стартовая точка для каждого типа проекта (не с нуля каждый раз)
- **SOP (Standard Operating Procedure)** — задокументированный процесс для каждого типа
- **Delivery time** — сокращение с 2 недель до 3 дней за счёт шаблонов
- **Команда агентов** — специализированные Claude subagents для каждого шаблона
- **Price premium** — быстрее = дороже (value-based, не time-based)

---

## Теория

### Проблема штучного производства

🎨 **Образ:** Повар который каждый день заново придумывает рецепт борща. Каждый раз ищет пропорции, забывает сколько соли, тратит час вместо пятнадцати минут. Шеф-повар пишет рецепт один раз — и повторяет его идеально за любое количество порций.

Каждый раз начинать с нуля — это дорого и медленно:

```
Проект 1: Newsletter Automation
- Настройка Gmail API OAuth: 4 часа
- Структура Cloudflare Worker: 3 часа  
- Telegram bot setup: 2 часа
- Итого инфраструктуры: 9 часов (из ~40 общих)

Проект 2: Newsletter Automation (другой клиент)
- Настройка Gmail API OAuth: 4 часа (снова!)
- Структура Cloudflare Worker: 3 часа (снова!)
- Telegram bot setup: 2 часа (снова!)
- Итого инфраструктуры: 9 часов (22% всего времени на то что уже делал)
```

После 5 похожих проектов ты мог бы работать вдвое быстрее — но каждый раз начинаешь заново.

🎨 **Образ:** Первый дом строишь 3 месяца — всё новое: где закупать материалы, как устроить фундамент, какая бригада надёжная. Десятый дом строишь 3 недели: материалы заказаны заранее у проверенного поставщика, бригада знает свои роли, типовые стены уже в чертежах. Дома разные снаружи — система одна внутри.

---

### Три типа шаблонов в Factory

🎨 **Образ:** У строителей есть три вида заготовок: типовые чертежи фундамента (одинаковы для всех домов), типовые планировки комнат (несколько вариантов), и финишная отделка под клиента (каждый раз своя). Три уровня шаблонов — три уровня скорости.

**Тип 1: Infrastructure Template**

Повторяющийся код который одинаков в каждом проекте:

```
template-base/
├── cloudflare-worker/
│   ├── worker.js              ← основной Worker с routing
│   ├── auth.js                ← OAuth helpers для Google/Microsoft
│   ├── telegram-bot.js        ← Telegram Bot базовый setup
│   └── kv-storage.js          ← helpers для Cloudflare KV
├── triggers/
│   ├── cron-template.ts       ← Trigger.dev cron job шаблон
│   └── webhook-template.ts    ← Webhook listener шаблон
├── utils/
│   ├── claude-client.js       ← Anthropic API wrapper с retry logic
│   ├── error-handler.js       ← стандартная обработка ошибок
│   └── logger.js              ← структурированное логирование
├── .env.example               ← всегда одинаковая структура
├── .gitignore                 ← стандартный
└── README-template.md         ← шаблон документации
```

Новый проект = `git clone template-base new-project-name`. Инфраструктура готова за 30 минут, не за 9 часов.

**Тип 2: Workflow Template**

Полный шаблон для конкретного типа проекта:

```
template-newsletter/           ← для Newsletter Automation
template-lead-gen/             ← для Lead Generation
template-exec-assistant/       ← для Executive Assistant
template-content-pipeline/     ← для Content Creation
template-crm-integration/      ← для CRM интеграций
```

Каждый содержит: базовую логику воркфлоу, типовые инструменты, CLAUDE.md со специализированным промптом, .env.example с нужными API ключами.

**Тип 3: CLAUDE.md Templates**

Специализированные инструкции для агентов под каждый тип задачи:

```markdown
# CLAUDE.md для Newsletter Automation Agent

Ты — агент автоматизации рассылки новостей.
Твоя задача: собирать новости, генерировать контент, координировать отправку.

## Правила работы:
- ВСЕГДА показывай превью до отправки
- Используй brand_guidelines.md для тона письма
- Если API вернул ошибку — логируй и продолжай с partial data
- Максимум 5 новостей за выпуск если не указано иное

## Формат каждой новости: заголовок + 2 предложения + ссылка
...
```

### 80% шаблон + 20% кастомизация

🎨 **Образ:** Пошив костюма в ателье. 80% — стандартные лекала которые портной использует годами: форма пиджака, ширина плеча, длина рукава. 20% — под тебя: твои мерки, выбранная ткань, цвет пуговиц. Клиент получает индивидуальный костюм. Портной не кроит с нуля каждый раз.

Это ключевое соотношение Factory:

**80% стандарт (из шаблона):**
- Структура файлов
- Подключение к API сервисам
- Error handling и логирование
- Telegram bot базовый функционал
- Handover документация (берёшь README-template.md, заполняешь)

**20% кастомизация (под клиента):**
- Конкретные источники данных клиента
- Бренд-голос и стиль контента
- Бизнес-правила (что считается "горячим лидом" для этой компании)
- Интеграция с конкретной CRM клиента
- Специфические уведомления и пороговые значения

Для клиента ты кастомизируешь 20% — но он получает 100% продукт. Для тебя 80% уже готово.

### Как Factory сокращает delivery time

**Без Factory:**
```
Неделя 1: настройка инфраструктуры + базовый воркфлоу
Неделя 2: кастомизация + тестирование + документация
Итого: 2 недели
```

**С Factory:**
```
День 1: clone template + настройка .env + первый запуск
День 2-3: кастомизация под клиента (20% логики)
День 4: тестирование + правки
День 5: handover + демо
Итого: 5 рабочих дней (1 неделя)
```

Вдвое быстрее при том же результате для клиента.

---

### Price Premium — быстрее = дороже

🎨 **Образ:** Срочная доставка. Обычная почта — 5 дней, $5. Курьер к вечеру — $50. Продукт тот же самый — конверт с документами. Но скорость стоит в 10 раз дороже. Клиент платит не за километры — за то что вопрос закрыт сегодня, а не в пятницу.

Это контринтуитивно, но работает. Клиент не платит за твоё время — он платит за результат. Если результат приходит быстрее — он ценнее.

**Позиционирование:**

❌ "Я могу сделать за 1 неделю вместо 2 потому что у меня шаблоны"

✅ "Благодаря специализации на этом типе проектов я запускаю систему за 5 дней. Для большинства клиентов это критично — чем раньше система работает, тем раньше экономия."

**Практическое ценообразование с Factory:**

| Тип | Без Factory | С Factory | Твой доход/час |
|---|---|---|---|
| Newsletter Automation | $2,000 за 2 недели | $2,200 за 5 дней | Вырос в 2.5x |
| Lead Gen Pipeline | $3,000 за 3 недели | $3,200 за 8 дней | Вырос в 2x |
| Executive Assistant | $4,500 за 3 недели | $5,000 за 10 дней | Вырос в 2x |

Клиент платит чуть больше и получает результат вдвое быстрее. В этом условном расчёте выручка за час твоей работы вдвое выше. Цифры иллюстративные: твои часы и цены будут другими, это не обещание дохода.

### Команда агентов для каждого шаблона

В каждом template-воркфлоу — специализированные subagents:

**template-newsletter:**
```
agents/
├── researcher.md     ← ищет и оценивает новости
├── writer.md         ← пишет контент в бренд-голосе
├── assembler.md      ← собирает HTML-письмо
└── coordinator.md    ← orchestrator всего процесса
```

**template-lead-gen:**
```
agents/
├── prospector.md     ← находит потенциальных клиентов
├── personalizer.md   ← пишет персонализированные письма
├── qualifier.md      ← оценивает качество лида
└── crm-updater.md    ← обновляет данные в CRM
```

Когда запускаешь новый Newsletter проект — берёшь готовых агентов из шаблона, меняешь только CLAUDE.md с деталями конкретного клиента.

### SOP для каждого типа проекта

🎨 **Образ:** Инструкция пилота в кабине самолёта. Перед взлётом — один и тот же чеклист: закрылки, давление, связь с вышкой. Пилот не импровизирует каждый раз. Это не значит что он робот — это значит что он не забывает проверить давление в шинах когда волнуется.

Standard Operating Procedure — документ для тебя (не для клиента). Как запустить проект этого типа шаг за шагом:

```markdown
# SOP: Newsletter Automation Project

## День 1: Setup (2-3 часа)
□ git clone template-newsletter [project-name]
□ Создать .env из .env.example, получить API ключи от клиента
□ Запустить базовый тест: python test_connections.py
□ Настроить Cloudflare Worker (wrangler deploy)
□ Первый тест запуска воркфлоу с mock данными

## День 2-3: Кастомизация (4-6 часов)
□ Загрузить brand_guidelines от клиента
□ Настроить источники новостей (Perplexity query, RSS feeds)
□ Настроить HTML-шаблон по бренду клиента
□ Настроить список получателей (test mode)
□ Telegram bot: добавить клиента как admin

## День 4: Тестирование (3-4 часа)
□ Полный прогон с реальными данными
□ Отправка тестового письма на свой email
□ Проверить логирование в Google Sheets
□ Исправить все issues

## День 5: Handover (2-3 часа)
□ Запись Loom walkthrough (20 мин)
□ Обновить README-template.md под этот проект
□ Финальный демо с клиентом
□ Передача доступов по чеклисту
□ Отправить финальное письмо о завершении проекта
```

SOP занимает 30 минут на создание — и экономит часы на каждом следующем проекте.

---

### Когда Factory окупается

🎨 **Образ:** Заточить пилу перед тем как пилить лес. Первые 20 минут уходят на заточку — и кажется что теряешь время. Но тупой пилой рубишь дерево за час. Острой — за 15 минут. Чем больше деревьев впереди, тем выгоднее потраченные 20 минут на заточку.

Честная оценка:

- **1-2 проекта одного типа:** ещё не окупилось создание шаблона
- **3-й проект:** шаблон начал экономить время
- **5-й проект:** ты в 2-3x быстрее новичка который делает с нуля
- **10-й проект:** Factory полностью сформирован, ты мастер этого типа

Начни строить шаблон после второго проекта одного типа — это правильный момент. Раньше — преждевременная оптимизация.

## Практика

**Задание: Создать свой первый шаблон**

1. Возьми воркфлоу который ты уже построил (Newsletter Automation из курса)

2. Создай папку `templates/newsletter-automation-template/`:
   - Скопируй все файлы проекта
   - Замени все client-specific данные на placeholder'ы (`[CLIENT_NAME]`, `[BRAND_COLOR]`, `[API_KEY]`)
   - Создай чеклист что нужно заменить при кастомизации

3. Напиши SOP для этого типа проекта (5 дней, как в примере выше):
   - День 1: что делаешь?
   - День 2-3: кастомизация — какие конкретные файлы меняешь?
   - День 4: тестирование — какие проверки запускаешь?
   - День 5: handover — какие документы создаёшь?

4. Оцени: если бы у тебя был этот шаблон с самого начала — на сколько дней быстрее был бы проект?

5. Рассчитай price premium: если без шаблона делаешь за 10 дней и берёшь $2,000 — за сколько дней с шаблоном и сколько стоит новая цена?

**Цель:** Один рабочий шаблон в папке `templates/`. Это первый кирпич твоего Factory.

## Частые ошибки

- **Масштабировать до того как есть SOP.** Без задокументированного процесса ты масштабируешь хаос. Сначала SOP для одного типа проекта → потом второй → потом помощник.
- **Слишком рано оптимизировать.** Шаблон после первого проекта — преждевременная оптимизация. После второго проекта ТОГО ЖЕ ТИПА — самое время.
- **Шаблон = копия последнего проекта.** Не копируй слепо. Убери client-specific данные, замени на плейсхолдеры, добавь чеклист "что заменить". Иначе следующий клиент получит данные предыдущего.
- **Не обновлять шаблоны.** API меняются, лучшие практики эволюционируют. После каждого 3-го проекта — ревью шаблона: что улучшить?

## Ключевые выводы

> 80% стандарт + 20% кастомизация — это формула Factory. Не 100% custom каждый раз.

> Быстрее = дороже. Парадокс Factory: меньше времени ты тратишь — больше можешь просить. Ценят результат, не процесс.

> SOP — для тебя, не для клиента. Документируй процесс чтобы следующий проект этого типа был автоматическим.

> Начни строить шаблон после второго проекта. Раньше — преждевременная оптимизация, позже — упущенное время.
