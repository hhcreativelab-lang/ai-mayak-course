# Урок 48: Модель фабрики: шаблоны и повторяемость

**Время:** ~25 мин теории + 30 мин практики

---

## Суть урока

Первый дом строишь 3 месяца. Десятый строишь 3 недели: у тебя уже есть шаблоны стен, проверенные поставщики, и бригада знает, что делать. Модель фабрики означает, что каждый новый проект похожего типа ты делаешь быстрее и дешевле предыдущего. А с клиента можно взять немного больше, потому что быстрый результат для него ценнее.

Если ты продаёшь AI-услуги как фрилансер или в свободное от основной работы время, так ты берёшь похожие проекты и не тратишь на каждый столько же часов, сколько на первый.

Примеры в уроке взяты из проектов с кодом: их собирают в Claude Code, о нём следующий модуль курса и углублённая библиотека. Понимать каждое название файла не нужно. Если ты пока работаешь без кода, бери сам принцип: шаблоном может быть набор промптов, структура коммерческого предложения или чеклист сдачи работы.

---

## Ключевые концепции

- **Фабрика**: система шаблонов, которая позволяет брать больше проектов: 80% стандартного и 20% под клиента
- **Проект-шаблон** (по-английски template repo, «шаблонный репозиторий»; репозиторием называют папку проекта, историю изменений которой хранит программа Git): стартовая точка для каждого типа проекта, чтобы не начинать с нуля
- **SOP** (Standard Operating Procedure, стандартная рабочая инструкция): записанный по шагам процесс для каждого типа проекта
- **Срок сдачи**: с шаблонами сокращается с 2 недель до 5 рабочих дней
- **Команда агентов**: субагенты Claude (subagents: помощники, у каждого одна узкая задача) для каждого шаблона
- **Надбавка за скорость**: быстрее значит дороже (цена по ценности результата, а не по затраченному времени)

---

## Теория

### Проблема штучной работы

🎨 **Образ:** Повар, который каждый день заново придумывает рецепт борща. Каждый раз ищет пропорции, забывает, сколько класть соли, и тратит час вместо пятнадцати минут. Шеф-повар записывает рецепт один раз и повторяет его без ошибок на любое число порций.

Каждый раз начинать с нуля дорого и медленно:

```
Проект 1: автоматическая рассылка новостей (Newsletter Automation)
- Настройка входа в Gmail (Gmail API, OAuth): 4 часа
- Основа на Cloudflare Workers: 3 часа
- Настройка Telegram-бота: 2 часа
- Итого на техническую основу: 9 часов (из ~40 общих)

Проект 2: автоматическая рассылка новостей (другой клиент)
- Настройка входа в Gmail (Gmail API, OAuth): 4 часа (снова!)
- Основа на Cloudflare Workers: 3 часа (снова!)
- Настройка Telegram-бота: 2 часа (снова!)
- Итого на техническую основу: 9 часов (22% всего времени на то, что ты уже делал)
```

После 5 похожих проектов ты мог бы работать вдвое быстрее, но каждый раз начинаешь заново.

🎨 **Образ:** Первый дом строишь 3 месяца. Всё новое: где закупать материалы, как заливать фундамент, какая бригада надёжная. Десятый дом строишь 3 недели: материалы заказаны заранее у проверенного поставщика, бригада знает свои роли, типовые стены уже есть в чертежах. Снаружи дома разные, а система внутри одна.

### Три типа шаблонов в фабрике

🎨 **Образ:** У строителей три вида заготовок: типовые чертежи фундамента (одинаковые для всех домов), типовые планировки комнат (несколько вариантов) и отделка под клиента (каждый раз своя). Три уровня шаблонов дают три уровня скорости.

**Тип 1: Шаблон технической основы**

Повторяющийся код, одинаковый в каждом проекте:

```
template-base/
├── cloudflare-worker/
│   ├── worker.js              ← основной Worker: принимает и распределяет запросы
│   ├── auth.js                ← вход через Google/Microsoft (OAuth)
│   ├── telegram-bot.js        ← базовая настройка Telegram-бота
│   └── kv-storage.js          ← работа с хранилищем Cloudflare KV
├── triggers/
│   ├── cron-template.ts       ← шаблон задачи по расписанию (Trigger.dev)
│   └── webhook-template.ts    ← шаблон приёма вебхуков
├── utils/
│   ├── claude-client.js       ← обращение к Anthropic API с повторными попытками
│   ├── error-handler.js       ← стандартная обработка ошибок
│   └── logger.js              ← запись событий в журнал
├── .env.example               ← всегда одинаковая структура
├── .gitignore                 ← стандартный
└── README-template.md         ← шаблон документации
```

(Задача по расписанию, по-английски cron job, запускается сама в заданное время. Вебхуком называют сообщение, которое одна программа отправляет другой, когда что-то произошло. В файле .env проект хранит настройки и секретные ключи.)

Новый проект = `git clone template-base new-project-name` (команда Git, которая копирует шаблон в новую папку). Техническая основа готова за 30 минут, а не за 9 часов.

**Тип 2: Шаблон рабочего процесса**

Полный шаблон для конкретного типа проекта:

```
template-newsletter/           ← автоматическая рассылка новостей
template-lead-gen/             ← поиск потенциальных клиентов
template-exec-assistant/       ← личный ассистент руководителя
template-content-pipeline/     ← подготовка контента
template-crm-integration/      ← подключение к CRM
```

В каждом лежат: основная логика процесса, типовые инструменты, файл CLAUDE.md со специальным промптом (в CLAUDE.md записаны инструкции, которые Claude Code читает, когда работает в проекте) и файл .env.example со списком нужных ключей API.

**Тип 3: Шаблоны CLAUDE.md**

Готовые инструкции для агентов под каждый тип задачи:

```markdown
# CLAUDE.md для агента автоматической рассылки

Ты агент автоматизации рассылки новостей.
Твоя задача: собирать новости, готовить текст, координировать отправку.

## Правила работы:
- ВСЕГДА показывай черновик письма до отправки
- Тон письма бери из файла brand_guidelines.md
- Если сервис вернул ошибку, запиши её в журнал и продолжай с теми данными, что есть
- Не больше 5 новостей в выпуске, если не указано иное

## Формат каждой новости: заголовок + 2 предложения + ссылка
...
```

### 80% шаблон + 20% под клиента

🎨 **Образ:** Пошив костюма в ателье. 80% составляют стандартные лекала, которыми портной пользуется годами: форма пиджака, ширина плеча, длина рукава. 20% делается под тебя: твои мерки, выбранная ткань, цвет пуговиц. Клиент получает костюм по своей фигуре. Портной не кроит каждый раз с нуля.

Это главное соотношение фабрики:

**80% стандартного (из шаблона):**
- Структура файлов
- Подключение к сервисам через API
- Обработка ошибок и запись событий в журнал
- Базовые функции Telegram-бота
- Документы для сдачи работы (берёшь README-template.md и заполняешь)

**20% под клиента:**
- Источники данных именно этого клиента
- Голос бренда и стиль текстов
- Правила бизнеса (кого в этой компании считают «горячим» клиентом)
- Подключение к CRM, которой пользуется клиент
- Свои уведомления и пороговые значения

Под клиента ты меняешь 20%, а он получает готовый продукт целиком. Для тебя 80% уже сделано.

### Как фабрика сокращает срок сдачи

**Без фабрики:**
```
Неделя 1: настройка технической основы + базовый рабочий процесс
Неделя 2: подстройка под клиента + проверка + документация
Итого: 2 недели
```

**С фабрикой:**
```
День 1: копия шаблона + настройка .env + первый запуск
Дни 2-3: подстройка под клиента (20% логики)
День 4: проверка + правки
День 5: сдача работы + показ клиенту
Итого: 5 рабочих дней (1 неделя)
```

Вдвое быстрее при том же результате для клиента.

---

### Надбавка за скорость: быстрее значит дороже

🎨 **Образ:** Срочная доставка. Обычная почта: 5 дней, $5. Курьер к вечеру: $50. Продукт тот же самый, конверт с документами. Но скорость стоит в 10 раз дороже. Клиент платит не за километры, а за то, что вопрос закрыт сегодня, а не в пятницу.

Звучит странно, но часто работает. Клиент платит не за твоё время, а за результат. Если результат приходит быстрее, он ценнее.

**Как об этом говорить:**

❌ «Могу сделать за 1 неделю вместо 2, потому что у меня шаблоны»

✅ «Я специализируюсь на этом типе проектов, поэтому запускаю систему за 5 дней. Для большинства клиентов это важно: чем раньше система работает, тем раньше начинается экономия.»

**Цены с фабрикой на примере:**

| Тип | Без фабрики | С фабрикой | Твоя выручка за час |
|---|---|---|---|
| Автоматическая рассылка | $2,000 за 2 недели | $2,200 за 5 дней | Выше примерно в 2.2 раза |
| Поиск потенциальных клиентов | $3,000 за 3 недели | $3,200 за 8 дней | Выше примерно в 2 раза |
| Личный ассистент руководителя | $4,500 за 3 недели | $5,000 за 10 дней | Выше примерно в 2.2 раза |

Клиент платит чуть больше и получает результат вдвое быстрее. В этом условном расчёте выручка за час твоей работы примерно вдвое выше. Цифры условные: твои часы и цены будут другими, и это не обещание дохода.

### Команда агентов для каждого шаблона

В каждом шаблоне рабочего процесса лежат готовые субагенты. Claude Code ищет их в папке `.claude/agents/` внутри проекта:

**template-newsletter:**
```
.claude/agents/
├── researcher.md     ← ищет и оценивает новости
├── writer.md         ← пишет текст в голосе бренда
├── assembler.md      ← собирает письмо в формате HTML
└── coordinator.md    ← управляет всем процессом
```

**template-lead-gen:**
```
.claude/agents/
├── prospector.md     ← находит потенциальных клиентов
├── personalizer.md   ← пишет персональные письма
├── qualifier.md      ← оценивает, насколько клиент подходит
└── crm-updater.md    ← обновляет данные в CRM
```

Когда запускаешь новый проект рассылки, берёшь готовых агентов из шаблона и меняешь только CLAUDE.md: вписываешь детали конкретного клиента.

### SOP для каждого типа проекта

🎨 **Образ:** Чеклист пилота в кабине самолёта. Перед взлётом он один и тот же: закрылки, давление, связь с вышкой. Пилот не импровизирует. Это не делает его роботом: просто он не забудет проверить давление в шинах, когда волнуется.

SOP (стандартная рабочая инструкция) пишется для тебя, а не для клиента: как шаг за шагом запустить проект этого типа.

```markdown
# SOP: проект «Автоматическая рассылка»

## День 1: Подготовка (2-3 часа)
□ git clone template-newsletter [project-name]
□ Создать файл .env из .env.example, получить у клиента ключи API
□ Запустить базовую проверку: python test_connections.py
□ Настроить Cloudflare Worker (wrangler deploy)
□ Первый пробный запуск процесса на тестовых данных

## Дни 2-3: Подстройка под клиента (4-6 часов)
□ Загрузить brand_guidelines клиента (правила его бренда)
□ Настроить источники новостей (запрос в Perplexity, RSS-ленты)
□ Настроить HTML-шаблон письма под бренд клиента
□ Настроить список получателей (тестовый режим)
□ Telegram-бот: добавить клиента администратором

## День 4: Проверка (3-4 часа)
□ Полный прогон на настоящих данных
□ Отправить тестовое письмо на свой адрес
□ Проверить запись событий в Google Sheets
□ Исправить все найденные ошибки

## День 5: Сдача работы (2-3 часа)
□ Записать видеообзор в Loom (20 мин)
□ Обновить README-template.md под этот проект
□ Финальный показ клиенту
□ Передать доступы по чеклисту
□ Отправить письмо о завершении проекта
```

На SOP уходит 30 минут, а экономит он часы на каждом следующем проекте.

### Когда фабрика окупается

🎨 **Образ:** Наточить пилу перед тем, как пилить лес. Первые 20 минут уходят на заточку, и кажется, что теряешь время. Но тупой пилой дерево пилишь час, а острой 15 минут. Чем больше деревьев впереди, тем выгоднее эти 20 минут.

Честная оценка:

- **1-2 проекта одного типа:** создание шаблона ещё не окупилось
- **3-й проект:** шаблон начал экономить время
- **5-й проект:** ты в 2-3 раза быстрее новичка, который делает всё с нуля
- **10-й проект:** фабрика сложилась, этот тип проектов ты знаешь досконально

Начинай собирать шаблон после второго проекта одного типа: это правильный момент. Раньше будет преждевременно.

## Практика

**Задание: создай свой первый шаблон**

1. Возьми работу, которую ты уже делал хотя бы один раз: услугу из своих пакетов или автоматизацию, если ты её уже собирал (в примере ниже это автоматическая рассылка, её собирают в углублённой библиотеке)

2. Создай папку `templates/newsletter-automation-template/` (вместо newsletter-automation подставь название своей работы):
   - Скопируй туда все файлы проекта: документы, промпты, таблицы, код, если он есть
   - Замени все данные клиента на метки-заглушки (`[CLIENT_NAME]`, `[BRAND_COLOR]`, `[API_KEY]`)
   - Составь чеклист: что нужно заменить при подстройке под нового клиента

3. Напиши SOP для этого типа проекта (5 дней, как в примере выше):
   - День 1: что делаешь?
   - Дни 2-3: подстройка под клиента: какие именно файлы меняешь?
   - День 4: проверка: что именно проверяешь?
   - День 5: сдача работы: какие документы готовишь?

4. Оцени: если бы этот шаблон был у тебя с самого начала, на сколько дней быстрее прошёл бы проект?

5. Посчитай надбавку за скорость: если без шаблона проект занимает 10 дней и стоит $2,000, сколько дней он займёт с шаблоном и какой будет новая цена? Сверься с примером из урока: вдвое быстрее и чуть дороже, то есть около 5 дней и около $2,200. Выручка за день тогда вырастает с $200 до $440.

**Цель:** один рабочий шаблон в папке `templates/`. Это первый кирпич твоей фабрики.

## Памятка: показатели эффективности фабрики

| Тип проекта | Без фабрики | С фабрикой | Экономия | Ставка за час |
|---|---|---|---|---|
| Автоматическая рассылка | 40 часов / 2 нед | 20 часов / 5 дней | 50% времени | $2,200 за 20 ч = $110 в час |
| Поиск потенциальных клиентов | 60 часов / 3 нед | 30 часов / 8 дней | 50% времени | $3,200 за 30 ч = $107 в час |
| Личный ассистент руководителя | 80 часов / 3 нед | 40 часов / 10 дней | 50% времени | $5,000 за 40 ч = $125 в час |
| Подготовка контента | 45 часов / 2 нед | 22 часа / 5 дней | 51% времени | $2,400 за 22 ч = $109 в час |
| Подключение к CRM | 70 часов / 3 нед | 35 часов / 8 дней | 50% времени | $4,200 за 35 ч = $120 в час |

**Вывод:** в этом примере фабрика примерно удваивает ставку за час: $50-60 без шаблонов → $107-125 с шаблонами при почти той же цене для клиента. Это расчёт для тренировки, а не прогноз заработка.

## Частые ошибки

- **Расти, пока нет SOP.** Без записанного процесса ты размножаешь хаос. Сначала SOP для одного типа проекта → потом для второго → потом помощник.
- **Делать шаблон слишком рано.** Шаблон после первого проекта преждевременен. После второго проекта ТОГО ЖЕ ТИПА самое время.
- **Шаблон как копия последнего проекта.** Не копируй вслепую. Убери данные клиента, поставь метки-заглушки, добавь чеклист «что заменить». Иначе следующий клиент получит данные предыдущего.
- **Не обновлять шаблоны.** Сервисы и их API меняются, приёмы работы тоже. После каждого третьего проекта пересматривай шаблон: что можно улучшить?

## Инструменты и ресурсы

- **GitHub**: закрытый репозиторий для хранения шаблонов (так они не теряются между компьютерами)
- **Cookiecutter** (на языке Python): программа, которая создаёт проекты из шаблонов командой в терминале
- **Notion**: [notion.com/templates](https://www.notion.com/templates), чтобы хранить SOP (удобный поиск и структура)
- **GitHub Actions**: автоматическая проверка шаблонов при каждом изменении
- **Loom**: [loom.com](https://www.loom.com/), запись видео по SOP, чтобы передать работу помощнику
- **Upwork**: [upwork.com](https://www.upwork.com/), поиск помощника на текущие задачи, когда фабрика уже работает
- **Fiverr**: [fiverr.com](https://www.fiverr.com/), быстрый поиск исполнителя на разовую задачу (дизайн, проверка)
- **Contra**: [contra.com](https://contra.com/), площадка для фрилансеров; на октябрь 2026 заявляет, что не берёт комиссию с исполнителей

## Ключевые выводы

> 80% стандартного + 20% под клиента: это формула фабрики. Не делай каждый проект целиком с нуля.

> Быстрее значит дороже. Парадокс фабрики: чем меньше времени ты тратишь, тем больше часто можешь просить. Клиент ценит результат, а не процесс.

> SOP пишется для тебя, а не для клиента. Записывай процесс, чтобы следующий проект этого типа шёл почти сам собой.

> Начинай собирать шаблон после второго проекта. Раньше будет преждевременно, позже ты теряешь время.
